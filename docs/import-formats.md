# 标准化文档导入处理流程

适用于管理员上传、预检和重建索引。三个入口使用相同的格式解析规则。文件保存了哪些内容、解析器提取了哪些内容、问答最终引用了哪些内容，可分别在原件、分块对照和问答依据中核对。

## 从接收到可引用

| 步骤 | 系统处理 | 管理员如何判断 |
|---|---|---|
| 1. 选择来源和版本 | 使用资料来源、文件名、原件 SHA-256、解析版本和选项区分导入。同部门更新同一份制度时复用来源，不同部门的同名文件可以分别维护。 | 检查来源是否正确；替换与另建应对应各自的文档身份。 |
| 2. 校验输入 | 校验文件名、空文件、扩展名、文件大小和格式结构，Office 包校验部件和解包大小，文本按可识别编码解码。每个文件独立限时解析。 | 损坏、密码保护、超限或依赖不可用时，按该文件的错误修正。繁忙时只重试临时失败项。 |
| 3. 提取结构 | 文本保留行，表格保留表区、表头和行，JSON 保留节点路径和所属实体，文档按章节、段落、幻灯片或原页组织。PDF 和图片记录可提取的页或帧。 | 在预检中选取一个业务事实，核对主体、字段、期间、单位及值是否来自同一条记录。 |
| 4. 形成分块 | 先按原始结构划分。超宽表行优先按完整字段分组，保留同一行的前列标签和值、各组列范围及 Excel 单元格坐标。超过 1,000 字符的长字段或正文优先在换行、标点或空格处分块，记录字符区间。 | 抽查尾部列或长字段的第二个分块，看它能否仍指向同一实体、字段和原件。 |
| 5. 报告覆盖 | 每个文件返回分块数、格式及警告。警告按原因汇总计数，各项最多列示 30 个位置。PDF 或图片另列提取页、识别页和遗漏页。 | 有警告的文件可保存有效部分。发布前应核对业务所需页面或字段是否在覆盖范围内。 |
| 6. 入库和版本切换 | 原件、分块和全文索引一起保存。失败的解析保留原活动版本。用新选项重建成功后启用新版，历史问答仍引用当时的原件和分块。 | 以目标问题验证检索。需要回退时，在“重新解析 → 索引版本”中核对版本号、解析版本、导入时间和分块数，选择已有版本并确认启用。切回已有版本直接使用其已保存的索引。 |

管理页按文件展示预检、警告和失败原因。在同一批中，“重试预检”只重试临时失败项；“确认导入已预览文件”只提交通过预检的文件。提交失败同样可单独重试。重试和确认均沿用选文件时的来源和解析选项。核对宽工作表时，在“分块对照”中选择数据行，再用“定位字段”直接查看原列和单元格；也可以用“上一组列”和“下一组列”浏览超过 64 列的范围。

## 按格式检查

以下逐项列出当前支持的 **18 个扩展名**。同一文件可以同时命中多种情况，尤其是混合 PDF、多表区工作簿和内嵌图片的 Office 文件。“核对”栏也列出格式特性带来的人工检查项。

| 扩展名 | 输入中可能出现的问题 | 实际处理与核对 |
|---|---|---|
| `.txt` | BOM、中文旧编码、换行差异、二进制伪装、只有空白、超长行、以空格排成多列 | 支持 UTF-8、GB18030、有 BOM 的 UTF-16/32；按连续行和空行分块并保留行号。二进制控制字符及空内容报错。固定宽度表应转成带列边界的表格再用于精确查数。 |
| `.md` | 分级标题和正文被空行分开，管线表格过长，转义竖线，代码围栏中出现标题或类似表格的字符，引用式链接或外部图片 | 保留常用 ATX 及单行 Setext 标题层级，识别带分隔行的管线表格，并为数据行附上列名。围栏内容保留为文本。多行标题、复杂嵌套块及外链图片应核对；不会取回外部图片正文。 |
| `.csv` | 总标题在列名前、全为文本的行难判表头、空白行、无表头、重复列名、空列名、逗号被引号包围、单条记录跨多行、编码或分隔符选错 | 按逗号、引号及记录边界读取，以原始起止行号定位。重复列名加列号，缺列名用“第 N 列”。全为文本等歧义会提示复核；可指定表头行或无表头模式。分号分隔或带地区小数格式的资料应先确认导出设置。 |
| `.tsv` | 与 CSV 相同的表头和编码问题，字段含 Tab，导出时 Tab 被改成空格 | 使用 Tab 分隔并保留引号内换行；在预检核对列数、空值和零值。一个字段对应多个业务字段时应重新导出。 |
| `.xlsx` | 首行为说明；多行/合并表头；多张工作表、同页多表、重复表头、合计脚注；百分比、前导零、日期与底层值不同；公式缓存缺失；隐藏页、行或列；超宽、损坏、外部链接、自定义格式 | 优先识别正式表格范围、空白分隔的表区、横向合并标题及下层年份。数据分块带原单元格和各级表头坐标。保留简单百分比、位数、千位分隔等显示格式与原值，复杂自定义数值格式提示核对；日期按 ISO 表达。公式保留表达式及已有缓存，未保存结果的公式会标记。默认排除隐藏内容，可显式纳入。附注、无分隔的并列表、交叉透视表与视觉留白的含义须复核。 |
| `.docx` | 样式标题、手工放大的伪标题、表中表、多行表头、纵横合并单元格，正文中的图片、浮动文本框、页眉页脚、脚注或批注 | 提取正文段落和表格行；识别常见标题样式/大纲级别，保留显式合并关系。缺少标题样式时，短的邻接上文以原段落号标注。绘图或嵌图会提示核对。代码所读范围为主文档正文；依赖页眉、脚注、批注、修订状态或视觉顺序的规则应人工核对，必要时另导出正文。 |
| `.pptx` | 幻灯片部件顺序不同于显示顺序；隐藏页、标题与要点、原生表格、截图或图表、母版与备注 | 遵循演示文稿清单顺序并保留页号；可识别的标题随正文保存，原生表格按行附字段。隐藏页默认排除。非文本对象或缺少可提取文字时提示核原页。演讲者备注、母版、关系图和图表图形的视觉含义需另行核对。 |
| `.html` | 标签嵌套、脚本样式混入、表头与数据分离、跨行跨列、漏写闭合标签、JS 动态生成数据、CSS 影响可见性 | 解析已有 HTML 文本，不执行脚本；排除 head、script、style 等内容，保留常见标题、表格、表头和源码行号。未闭合的表格尽量恢复并提示。动态渲染页应导出含实际内容的版本；CSS 显隐或复杂排版可能与浏览器显示不同。 |
| `.htm` | 同 HTML，旧页面常见 GB 系编码和布局表格 | 与 HTML 使用同一解析器和来源定位。结构表与布局表外观相近，应检查分块中是否确有业务表头。 |
| `.json` | 多个实体拥有同名指标，标签、编号和数值分布在父子层，键含 `/` 或 `~`，重复字段、深层对象、精确小数、空数组和 null | 逐节点保存 JSON Pointer 和所属记录位置。嵌套指标沿父层传递真实名称、标题及可识别的代码、编号（例如 `asset_code`、`projectID`、设备编号），并记录每个编号原来的字段路径。更新时间和任意属性保留在原节点。最多继承 16 项标识，单项值最多 140 字符，超出时提示复核。数字保留原文件字面值。重复键或无效 JSON 报错。无标签的嵌套字段保留路径。 |
| `.jsonl` | 行与行相似，空行，某一行语法错误，一条记录被拆成多行，精确数值 | 跳过空行；每一非空行须能单独解析。分块包含物理行号及行内 Pointer；坏行报行号，整文件退回，避免提交部分记录。 |
| `.ndjson` | 同 JSONL，事件日志可能存在不同版本的字段和类型 | 与 JSONL 走同一路径。即使行内节点路径相同，源行号仍不同；应核对时间、单位和字段类型是否在该事件中有定义。 |
| `.pdf` | 密码、缺字体映射、双栏错序、跨页表头、扫描页、文字与嵌图同页、无内容空页或 OCR 误识 | 逐页提取文字层。可识别的文字优先保留；有内容但无文本的页在 OCR 关闭时列入遗漏页。OCR 开启时可补识别扫描页，也可指定最多 5 个原页号补识别含图片的页。原文和 OCR 片段分别定位。金额、负号、小数及跨栏关系应核对原页。 |
| `.png` | 截图、透明背景、小字、图形、超大尺寸、看似表格但没有单元格结构 | 需启用本地 OCR；按图页输出文字和来源。无可辨文字或尺寸超限会提示。纯视觉图形及表格行列关系需对照原图。 |
| `.jpg` | 手机旋转照片、透视、阴影、JPEG 压缩、编号与小数模糊 | OCR 前按 EXIF 方向处理并缩放；照片方向、识别金额、单据编号应人工核验。严重透视建议重新拍摄或提供原始电子版。 |
| `.jpeg` | 同 JPG，扩展名与实际编码可能不符 | 与 JPG 共用 JPEG 解码和 OCR，引文定位到原图；扩展名与图像格式不符时退回。 |
| `.tif` | 多帧扫描、方向各异、个别空白帧、页数或像素超限 | 逐帧识别，保留原帧号；单帧无字时记录遗漏；所有帧无字或超过页数上限时退回，支持拆分后重新导入。 |
| `.tiff` | 同 TIF，历史扫描件可能模糊、倾斜、重影 | 与 TIF 共用多帧规则。逐帧核对记录序号、换页处数值和图章覆盖区域。 |

## 预检、纠正与验收

管理员可在“导入管理”先预检。HTTP 预检接口为 `POST /api/documents/inspect`，导入接口为 `POST /api/documents`，均使用 multipart 表单。文件字段为 `files`，来源为 `source_key`，解析设置放在 `options` JSON 中。每次最多 8 个文件，单文件 20 MiB，请求总量 48 MiB。预检只展示解析结果；提交或重建后才切换可检索版本。

| 情况 | 选项或行动 | 验收 |
|---|---|---|
| 第 1 行说明、第 2 行标题、第 3–4 行共同定义字段 | 预检自动识别，必要时填写 `{"header_rows":[3,4]}`；行号从 1 起，须连续。CSV/TSV 用物理起始行号，Excel 用工作表行号，Word/HTML 表内用表格行序号。一个导入请求的设置应用于其中的文件。 | 核对一个跨年样本的数据值、年份、指标及原件坐标。 |
| 第一行直接就是业务记录 | 使用 `{"headerless":true}`。 | 第一行仍能检索，系统以列号表述，待确证字段语义。 |
| 有隐藏草稿或需要检索的隐藏工作表 | 默认排除。经资料负责人确认后可用 `{"include_hidden":true}` 重新预检。 | 对比预检中的警告与分块，不应将隐藏状态视作下载原件的权限边界。 |
| PDF 第 2、5 页嵌图需要识别 | 在本地 OCR 已启用的情况下使用 `{"ocr_pages":[2,5]}`。指定页优先，其他无文字层页在覆盖报告中标出。 | 查找这两页独有的文字，并从引用核对同一页。 |
| 规则升级，或管理员修正了设置 | 用导入管理的重建功能，或 `POST /api/documents/{id}/reindex`。 | 比较两次导入的字段对应、遗漏页和检索结果；已有会话可查看原引用版本。 |
| 重建后的版本需要回退 | 在重新解析对话框选中同一资料的历史版本并确认恢复。接口为 `GET /api/documents/{id}/versions` 和 `POST /api/documents/{id}/restore/{version_id}`。 | 当前检索立即指向选定的索引，原件和各版历史引用仍可打开。并发更新时按最新活动版本重试。 |

文本提取预算含来源位置，共 400 万字符、20,000 个片段。表格最多 50,000 行、512 列，工作簿扫描单元格总量上限 200 万。PDF/PPTX 最多 1,200 页/张。Office 包展开总量 64 MiB，单部件 16 MiB。独立解析进程时限 40 秒，OCR 单文件最多 5 页，每帧最多 1,200 万像素、最长边 10,000 像素。运行实例的实际可用格式由 `GET /api/formats` 给出。

异常文件不会通过修改扩展名自动转换格式。音视频、旧版二进制 Office、其他压缩包、需浏览器执行脚本才能产生的内容，应先导出成受支持的格式。任意损坏方式、视觉版式和业务含义都可能超出自动识别范围，验收应包括来源核对和至少一个有已知答案的业务问题。

### 常见的其他输入

| 收到的资料 | 入库前的处理 | 转换后优先核对 |
|---|---|---|
| 旧版 Office `.xls`、`.doc`、`.ppt`，含宏工作簿 `.xlsm`、二进制工作簿 `.xlsb` | 由资料负责人用原应用另存为受支持的 Office 格式。需要宏或外链计算的表先在受控环境完成计算并保存结果。 | 日期、金额、公式缓存、隐藏页、页数/张数和可见表区。 |
| 开放文档 `.ods`、`.odt`、`.odp`，RTF、电子书、专有排版文档 | 表格优先导出 XLSX/CSV，正文优先 DOCX/HTML，需要固定原页时导出带文字层的 PDF。 | 分节次序、合并表头、脚注、图片说明和页码对应。 |
| XML、YAML、数据库转储、业务系统专有导出 | 对照业务定义导出 JSON/JSONL 或带字段名的 UTF-8 表格。查询在线指标时也可配置该系统的只读接口。 | 主键、父子记录、日期的时区、精确小数、零与缺失值。 |
| ZIP/RAR、邮件及其附件、网页链接、仅凭登录态才能打开的页面 | 将需要阅读的正文和附件分别导出为支持格式，先核对资料归属。上传地址文字只会索引地址本身。 | 同名附件的来源、附件与正文的关系、动态页面是否已包含实际数据。 |
| 音频、视频、手写扫描、复杂工程图或图表 | 提供经核对的转写、图表原始数据，或带说明与原图的文档。上传纯扫描资料前检查 OCR 能力。 | 说话人、时点、图例、坐标轴、单位、负号、手写数字和跨页续表。 |

## 导入结果如何处置

| 结果 | 定位问题 | 后续动作 |
|---|---|---|
| 文件退回 | 无文本、编码错误、重复 JSON 键、坏结构、密码、依赖未就绪、超时或超过资源上限。错误带文件名，JSONL/NDJSON 尽可能带坏行号。 | 保留源件，按原因重新导出、解锁、拆分或启用所需组件，再重传。 |
| 暂时繁忙 | 解析工作槽正在使用。 | 等工作槽释放，重试该文件。 |
| 提取了部分内容 | PDF 的无文本页、个别 OCR 帧没有清晰文字，或图形、嵌图需要对照。可从报告的页清单或警告位置回原件检查。 | 找到用户关心的页，选择补 OCR、导出含可复制文本的原件，或将已核对的部分纳入知识库。 |
| 字段含义待确认 | 表头全为文本、无表头、标题与记录之间有空行、手工空格形成布局、多张表紧密相邻或某字段跨多列。 | 核对首条、中间条、末条；确认标题、单位和数据值属于同一表区。必要时给出正确表头行，或将不同表区分开导入。 |
| 数据能检索但不宜直接作答 | Excel 公式缺缓存、缓存陈旧、计算错误、条件格式或地区格式影响显示；PDF/OCR 中的符号与单位可能读错；表格里的零、空值、缺失值和脚注可能混用。 | 回到原件核对业务定义及计算口径。在桌面应用重新计算并保存公式，或导出经核准的值；对币种、数量级和否定条件设置独立验收题。 |
| 原件与分块均正确但问答漏答 | 检索排序、摘录、问题分流等后续环节也会影响答案。 | 先在分块对照中记录目标文档版本和位置，再从检索评测查看候选与排名；只有原始结构有误时才需要重建索引。 |

预检、导入和重建都返回同一个 `coverage.status`。`indexed` 表示已有可检索片段且解析器未报告待复核项。`partial` 表示已知有页面或图帧遗漏，可从 `skipped_pages` 查页码。`review` 表示已有分块，同时存在警告或使用了 OCR，需要对照原件。旧版本的导入报告可能为空。整文件退回时，原因在逐文件错误中，原活动版本继续提供查询。

验收时每种格式至少选一个有已知答案的正例和一个应当提示、拒绝或部分导入的反例。表格分别抽首条、中间、末条，检查主体、字段、单位、期间、值和原件坐标。多记录或多章节资料要增加一条同名实体或同名条款的反例。依次记录原件摘要和解析版本、正确分块、实际入选依据、最终回答和引用位置，便于判断损失发生在哪一步。相关测试包括[各格式基础行为](../tests/test_documents.py)、[结构、覆盖与选项回归](../tests/test_import_formats.py)、[真实 OCR 回归](../tests/test_ocr.py)和[导入、重建与历史兼容](../tests/test_import_lifecycle.py)。
