# 业务接口响应与指标口径

管理员在“数据接口配置”中可为文本筛选字段填写允许的值。自然语言中出现明确值时，工作台会绑定该字段；找不到合适值或同一标量字段出现多个值时，页面提示补全条件。精确金额参数应以字符串形式传入，例如 `{"params":{"amount":"123456789012345678.010"}}`。问答中的自然语言金额和管理页输入也以原始十进制文本发送。

## 对齐业务状态与分页

假设接口合同约定，业务成功时返回如下内容。

```json
{"code":"OK","data":{"total":75,"has_more":true,"rows":[{"区域":"华东","库存量":12}]}}
```

在接口编辑页把记录路径填为 `data.rows`，在“业务口径与响应规则”填入以下响应规则。成功值使用接口实际类型，字符串 `"0"` 和数字 `0` 分开核对。

```json
{"success_path":"code","success_value":"OK","total_path":"data.total","has_more_path":"data.has_more"}
```

该例中查询能回答“共有 75 条记录”，依据会标明本次返回 1 条。工作台发起一次只读请求，由连接器适配的业务系统决定返回哪一页。需要全表合计、排行时，先核对数据是否完整。有明确的全量返回契约、且没有总数元数据的接口，可设置 `{"complete":true}`。总数大于本页条数或 `has_more` 为真时，仍按部分数据处理。新配置的路径不存在、元数据类型不符或业务状态失败时，页面会说明接口问题。

兼容已有接口时，会读取包装对象顶层的 `total` 和 `has_more`，以及常见的 `success:false`、`ok:false`、`code` 搭配 `message/msg` 的业务状态。上游使用自定义成功码时应填写精确判据。普通响应未提供总数时，依据展示本次实际返回的行数。

## 配置指标

在“指标定义”中填写上游字段及业务已确认的口径。

```json
[
  {"field":"库存量","label":"实物库存","aliases":["在库数量"],"unit":"件","definition":"本仓已入库且未出库的实物件数","additive":true},
  {"field":"利用率","label":"仓容利用率","unit":"%","definition":"已占用容积除以可用容积","additive":false}
]
```

求和需要匹配到一个可加指标、完整的记录范围，并且每行均有可解析的指标值。比率按业务定义处理。数字排名和极值也核对完整范围，排名正文最多列出 20 项。业务系统已汇总好的结果，适合配置为专门的查询接口。“合计库存量”还需要连接器返回的各行粒度可相加；在声明可加前，管理员应核对小计、重复记录以及不同计量单位。
